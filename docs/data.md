# 데이터 설명서

> **이 프로젝트의 모든 데이터는 학습용 가상 값이다.** 영양 수치, 가격, 분량, 조리 시간, 보관 기간, 유통기한, 재고, 가족 구성은 모두 이 프로젝트가 임의로 정한 값이며 실제 식품 성분표·시세·식품 안전 기준과 대조하지 않았다. 알레르기 항목은 목록 대조용이며 건강·의료 판단 근거가 아니다.

생성 스크립트는 `scripts/`에 있고 난수를 쓰지 않아 같은 입력이면 항상 같은 결과가 나온다. 결과는 `data/`에 있고 커밋하지 않는다. 프로그램은 `*.json`을 읽고, `*.csv`는 사람이 표로 보기 위한 용도다(CSV를 고쳐도 반영되지 않는다. 값은 스크립트에서 고친다).

생성 순서와 명령(프로젝트 루트에서):

```bash
uv run python scripts/ingredients.py     # 재료 사전 120
uv run python scripts/recipes.py         # 레시피 60 (재료 사전과 이름 대조)
uv run python scripts/household.py       # 우리 집 상태 (--base-date 로 기준 날짜 변경)
uv run python scripts/substitutes.py     # 대체 재료 규칙 40
uv run python scripts/storage_notes.py   # 보관·위생 노트 40
```

스크립트끼리 `from ingredients import ...`로 서로 가져오므로 `scripts/` 안의 파일을 경로로 직접 실행한다.

## 파일별 설명

| 파일 | 개수 | 내용 |
|---|---|---|
| `ingredients.json/.csv` | 120 | 이름, 분류, 단위(g/ml/개), 단위당 g, 100g당 영양 5종, 알레르기 분류, 단위당 가격(원), 보관법 |
| `recipes.json/.csv` | 60 | id(R001~), 이름, 인분, 태그, 필요 장비, 재료와 분량, 단계(설명·분·사람이 붙는지·장비·앞 대기와 동시 가능 여부) |
| `household.json`, `pantry.csv` | 1세트 | 기준 날짜, 가족 4명(알레르기), 보유 장비, 주간 예산·이미 쓴 금액, 냉장고 재고 34종(유통기한) |
| `substitutes.json/.csv` | 40 | id(S001~), 원래/대체 재료, 무게 비율, 맛·식감 차이, 검색용 `text` |
| `storage_notes.json/.csv` | 40 | id(T001~), 재료, 상황, 보관 기간(일), 주의점, 검색용 `text` |

## 단위와 환산

- 재료 분량의 단위는 재료 사전의 `unit`(g, ml, 개)을 따른다. 물은 재료로 세지 않는다.
- 영양은 항상 **100g당** 값이다(JSON). 개·ml 단위 재료는 `grams_per_unit`(개: 1개의 무게, ml: 밀도)로 g으로 바꾼 뒤 계산한다. 보기용 CSV의 영양 열은 1g당으로 환산한 값이다.
- 가격은 **단위당** 가격이며 필요한 분량을 곱해 계산한다(구매 단위 올림 없음).

## 우리 집 상태 (기준 날짜 2026-10-23, 금요일)

- 가족: 아빠 42, 엄마 40, 첫째 10(**땅콩 알레르기**), 둘째 6.
- 장비: 가스레인지, 에어프라이어, 전자레인지, 믹서, 밥솥. **오븐 없음.**
- 예산: 주간 15만 원 중 9만 원 사용 → 남은 6만 원.
- 질문에서 함정이 되도록 일부러 넣은 재고: 유통기한이 지난 플레인요거트, 오늘 만료인 방울토마토, 땅콩버터, 3일 이내 상하는 재고 다수.

## 단계 표시의 의미 (조리 시간 계산용)

- `active=true`: 사람이 붙어서 하는 단계(썰기, 볶기). 사람은 한 명이라 서로 겹치지 못한다.
- `active=false`: 대기 단계(끓이기, 재우기, 굽기). 그동안 다른 단계를 할 수 있다.
- `parallel=true`: 앞의 대기 단계가 도는 동안 겹쳐 할 수 있다고 **사람(Claude)이 표시한** 단계. 레시피 13개에만 있으며 검증되지 않았다.
